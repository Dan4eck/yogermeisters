# Yogermeisters — короткий отчёт об оптимизации

Дата фиксации отчёта: 2026-04-28

## Что было проблемой

Главный блокер загрузки — hero-видео на главной странице:

- исходный MP4 весил примерно **24 MB**;
- видео начинало грузиться сразу при открытии страницы;
- не было отдельного `poster`, поэтому первый экран мог дольше выглядеть пустым/тяжёлым;
- изображения ниже первого экрана частично грузились без lazy loading.

## Что изменено

### 1. Hero-видео

Исходное видео из `attached_assets/yoga_ubud_preroll_Copy_01_1765386774436.mp4` заменено в интерфейсе на оптимизированные публичные версии:

- `client/public/assets/videos/hero.mp4` — около **1.9 MB**;
- `client/public/assets/videos/hero.webm` — около **1.8 MB**;
- `client/public/assets/videos/hero-poster.jpg` — около **253 KB**.

В `Hero.tsx` добавлена отложенная загрузка через `IntersectionObserver`: видео начинает грузиться только когда hero-секция нужна пользователю. До загрузки показывается poster.

### 2. Lazy loading изображений

Добавлены безопасные браузерные оптимизации:

- `loading="lazy"` для изображений ниже первого экрана;
- `decoding="async"` для картинок внутри retreat-страниц;
- `loading="eager"` для главной обложки страницы ретрита, потому что она видна сразу;
- `preconnect` к Selectel CDN для видео-отзывов.

### 3. Фото преподавателя

Была попытка пережатия about-фото:

- `100 KB → 16 KB`

Но визуально качество стало слишком низким. Эта оптимизация отменена.

Важно: **не использовать** `client/public/assets/images/teacher-bamboo.jpg` как замену about-фото. Эта 16KB-версия была удалена.

Текущий правильный источник:

- `attached_assets/teacher-portrait-bamboo-wall.jpg` — около **100 KB**.

Для него оставлены только безопасные атрибуты:

- `loading="lazy"`;
- `decoding="async"`.

## Прикидка эффекта

| Ресурс | Было | Стало | Эффект |
|---|---:|---:|---:|
| Hero MP4 | ~24 MB | ~1.9 MB | примерно **-92%** |
| WebM-альтернатива | — | ~1.8 MB | более лёгкий формат для поддерживаемых браузеров |
| Poster hero | не было | ~253 KB | быстрее визуальный первый экран |
| About-фото | ~100 KB | ~100 KB | качество сохранено |

Главная экономия — около **22 MB** на hero-видео. Это должно заметно ускорить первый заход, особенно на мобильном интернете.

## Что не менялось

Фотографии ретрита Чиралы (`attached_assets/cirali/*`) этой локальной оптимизацией не пережимались. Они уже лежали в проекте как в основном 1280px-файлы. Если часть из них выглядит мыльно на больших/Retina-экранах, нужны более качественные оригиналы этих конкретных фото.

## Следующие возможные шаги

1. Найти оригиналы фото Чиралы и заменить текущие 1280px-файлы на веб-версии 1920–2560px с разумным JPEG/WebP quality.
2. Сделать code splitting для JS-бандла.
3. Добавить cache headers для production static assets.
4. Рассмотреть self-hosted шрифты вместо Google Fonts.
