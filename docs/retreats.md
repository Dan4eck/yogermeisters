# Retreat Pages Guide

## Главная страница V3

Текущая главная использует `homepage-v3/sections/retreats/RetreatsSection.tsx`.
На десктопе от 1000 px все четыре карточки помещаются в один ряд с одинаковой шириной и высотой;
на узких экранах работает карусель.

Карточки используют `/api/retreats` со статическим fallback из `@shared/retreat-content`.
Порядок V3: Шри-Ланка, Чиралы, Непал, горный ретрит. Недоступные в ответе API записи пропускаются.
Шри-Ланка открывает `/retreats/sri-lanka-yoga-tour`: 24 февраля — 3 марта 2027, €1199.
Существующие карточки сохраняют своё наполнение и детальные страницы.

## Детальные страницы и прежняя секция V2

Эта инструкция описывает текущую V2-архитектуру ретритов. TypeScript-файлы в `shared/retreats/` задают начальный
фиксированный набор, а после seed рабочие данные хранятся в PostgreSQL и редактируются через admin API.

## Где лежат данные

- `shared/retreats/cirali.ts` — ретрит Чиралы
- `shared/retreats/nepal.ts` — ретрит Непал
- `shared/retreats/mountains.ts` — горный ретрит
- `shared/retreats/sri-lanka.ts` — Шри-Ланка, программа и переводы RU/EN
- `shared/retreats/experience.ts` — структура визуального лендинга
- `shared/retreats/types.ts` — типы контента
- `shared/retreats/index.ts` — сборка, локализация, фильтрация и поиск ретритов

Главная секция ретритов и детальная страница читают `/api/retreats`, используя `@shared/retreat-content` как
типизированный статический fallback. API не позволяет добавлять или удалять ретриты.

## Как устроен ретрит

Каждый ретрит — это объект `RetreatSeed`:

- `title`, `location`, `startDate`, `endDate`, `dateLabel`, `price`, `bookingUrl`, `coverImage`, `status`
- `translations` для RU/EN полей верхнего уровня
- `blocks` для длинного контента детальной страницы
- необязательный `experience` для визуальной программы по дням; при его наличии страница использует новый шаблон

Поддерживаемые блоки:

- `paragraph` — обычный абзац
- `heading` — подзаголовок
- `image` — изображение по имени файла
- `callout` — выделенная плашка
- `countdown` — таймер/ценовой блок

Порядок блоков задаётся через `sortOrder`.

## Визуальная программа

`client/src/components/retreats/RetreatExperiencePage.tsx` и соседний CSS module реализуют шаблон в палитре V3:
первый экран с местом, датами и ценой, проживание, навигация по датам, программа и заявка в Telegram.
Отдельная вводная секция, нумерованные подписи разделов и повторяющие расписание акценты дней не выводятся.
В `experience` задаются тексты этих разделов, фотографии и массив `days`.
Каждый день содержит ISO-дату, заголовок, краткое описание, нагрузку, акценты, полное расписание и примечание.
Дни недели вычисляются из даты. Полное расписание всегда видно: компактные строки с отдельной колонкой времени, без раскрытия и линий между пунктами.
Для панорамных дней номер, дата, заголовок и описание расположены на фото; ниже — расписание и дополнительный снимок.

Варианты `layout`: `text`, `split`, `panorama`, `collage`. Изображения имеют `src`, `alt` и необязательный `caption`.
Используются локальные изображения из `/assets/`; все выбранные файлы Шри-Ланки находятся в
`client/public/assets/retreats/sri-lanka/` в WebP. Исходные пользовательские файлы не изменялись.

Поле `experience` хранится в существующем `retreats.data` JSONB: SQL-миграция не требуется.
Admin API валидирует его и возвращает через публичную локализованную модель.
Перевод `translations.ru.experience` заменяет всю программу для русского языка; база содержит английскую.
В `PATCH` нужно передавать целый `experience`, а при правке переводов — целый `translations`.
Старые записи без `experience` продолжают использовать `blocks`.

## Добавление Шри-Ланки в базу

Предварительная проверка без подключения к БД:

```bash
npm run db:seed:retreat -- sri-lanka-yoga-tour
```

Для согласованной публикации сначала доставьте код и assets обычным GitHub/Railway-процессом.
Затем в целевом окружении с `DATABASE_DIRECT_URL` или `DATABASE_URL`:

```bash
npm run db:seed:retreat -- sri-lanka-yoga-tour --apply
```

Команда вставляет только выбранный ретрит и сохраняет существующую запись с тем же slug.
Она не трогает курсы, пользователей и другие ретриты. Уже существующую запись обновляйте через admin API.
После вставки проверьте публичные список и детальную страницу на RU/EN. Успешный ответ API имеет приоритет
над локальным fallback, поэтому для появления карточки на работающем сервере нужна запись в его базе.

В программе 2027 года дата/адрес Ecstatic Dance отмечены как требующие подтверждения.
Для рейса 02:40 указан предварительный трансфер 20:00–20:30 накануне вместо исходных 22:00–22:30:
это учитывает 2,5–3,5 часа дороги и прибытие примерно за три часа. Время нужно согласовать по билетам и аэропорту.
Состав стоимости и условия оплаты уточняются через Telegram; неподтверждённые включения не обещаются.

## Как редактировать

Для рабочих изменений используйте admin API из `docs/admin-api.md`. Файлы в `shared/retreats/` меняйте только когда
нужно изменить исходные данные для новой установки.

Для RU-версии меняйте поля внутри `translations.ru`. Для EN-версии меняйте базовые поля или `translations.en`, если оно используется.

После правки seed-файлов:

```bash
npm run check
npm run build
```

Повторный seed не перезаписывает ретриты, которые уже есть в БД, поэтому опубликованный контент не будет случайно
заменён содержимым TypeScript-файлов.

## Статусы

- `active` — ретрит доступен
- `archived` — ретрит остаётся видимым, но считается прошедшим/недоступным
- `draft` — черновик

Главная секция V2 всегда строит три карточки в фиксированном порядке: Непал, Чиралы, горный ретрит. Доступность кнопки определяется статусом и датой окончания.
